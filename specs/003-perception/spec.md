# Feature Specification: 感知系统（Perception System）

**Feature Branch**: `003-perception`
**Created**: 2026-08-07
**Status**: Draft
**Input**: User description: "实现 AutoGLM 的效果，可以自动观察和（后续）自动操作。增加一个视觉模型，多模型协调，通过事件机制进行视觉/音频消息注入。视觉系统只在值得关注时自动输入信号到思考流；或者模型可以主动观察屏幕/摄像头。人类按快捷键触发视觉和音频输入（录屏和录音）。"

## 核心定位

感知系统为数字生命增加"看见"和"听见"的能力。它的本质是**一种新的事件来源**：视觉/音频传感器经过独立的视觉模型"消化"成结构化描述后，通过现有的事件机制注入主意识的思考流。对主意识而言，一条感知信号和一条飞书消息没有区别——都是它需要响应的事件。

本期只做**观察**，不做自动操作；输出仍走飞书文字（后续可扩展语音输出）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 人类快捷键触发感知（Priority: P1）

人类在电脑前工作时，按下全局快捷键（第一次按下开始录屏+录音，再次按下结束），系统自动录制一段屏幕画面和麦克风音频。录制结束后，这段视听素材经过视觉模型和语音转写模型预处理，结合主意识当前正在做的事（精简上下文），由视觉模型生成一段结构化理解，然后作为"感知信号"事件注入主意识。主意识在下一轮思考时看到它，自行决定如何回应（通过飞书文字回复、调用工具、或忽略）。

**Why this priority**: 这是感知系统最核心、最具独立价值的能力。它让数字生命第一次能"看到"人类当前面对的画面、"听到"人类当前说的话——这是 AutoGLM 形态的基础。单这一个能力就是可独立交付、可独立演示的 MVP。

**Independent Test**: 人类按下快捷键、完成一次录制 → 主意识收到感知信号事件并在飞书对话中给出基于画面内容的回应。整条链路不依赖任何其他 user story。

**Acceptance Scenarios**:

1. **Given** 主意识处于空闲（BLOCKED），**When** 人类按快捷键录制 10 秒屏幕（画面显示某只股票行情），**Then** 主意识被唤醒，其回应内容能体现它看到了"股票行情"这个画面要素。
2. **Given** 主意识正在处理另一件事（RUNNING，处于 LLM 调用之间），**When** 人类按快捷键录制，**Then** 不打断当前推理；感知信号被注入内存池，主意识在下一轮思考时自然看到。
3. **Given** 多实例部署（多个数字生命），**When** 人类按快捷键，**Then** 感知信号被路由到配置指定的默认实例（而非错误地发到所有实例或丢失）。
4. **Given** 录制过程中包含人类说话，**When** 预处理完成，**Then** 视觉模型的理解结果中包含转写后的语音文字。
5. **Given** 人类按下第一次快捷键后长时间不按第二次，**When** 达到最大录制时长，**Then** 系统自动结束录制并处理（不无限录制）。

---

### User Story 2 - 模型主动观察（Priority: P2）

主意识在思考过程中，可以主动调用"观察"类工具（看屏幕、看摄像头、听麦克风），即时获取当前环境信息。这是模型自己决定"我现在需要看一眼"。工具调用是同步的：模型调用 → 工具内部走与快捷键相同的视觉/音频流水线 → 结构化结果作为工具返回值送回模型。

**Why this priority**: 这补全了"被动接收"之外的能力——模型主动的、按需的观察。它让数字生命从"等人类喂信息"变成"自己会看"。优先级低于 P1 是因为它复用 P1 的流水线，且日常价值低于人类主动触发。

**Independent Test**: 主意识被任意事件唤醒后，调用观察工具 → 返回值是对当前屏幕的结构化描述。可独立于 P1 测试（P1 未实现时也能单测工具）。

**Acceptance Scenarios**:

1. **Given** 主意识在处理消息时调用了"看屏幕"工具，**When** 工具执行，**Then** 返回值包含当前屏幕画面的结构化描述（如"画面上有浏览器、代码编辑器、终端"）。
2. **Given** 主意识调用"听麦克风"工具，**When** 周围有人说话，**Then** 返回值包含转写后的文字。
3. **Given** 工具被调用，**When** 处理完成，**Then** 结果作为普通工具返回值进入主意识的思考流（不产生新事件，因为这是模型主动发起的）。

---

### User Story 3 - 视觉模型带精简上下文理解（Priority: P1）

视觉模型在理解录屏/录音时，不是"白纸"地看，而是带着主意识当前正在做的事的背景：最近几轮对话、当前在处理的任务、（如有）历史会话摘要。这样它能判断"画面里的东西和当前任务有什么关系"，而非孤立描述。这个"精简上下文"完全只读地从主意识的数据源提取，不修改主意识的会话存储。

**Why this priority**: 这是感知系统真正"有用"的关键——没有上下文，视觉模型只能给出泛泛的画面描述；有上下文，它才能给出"和当前任务相关"的理解。它是 P1/P2 能否产生价值的乘数器，和它们绑定，所以同为 P1。

**Independent Test**: 触发一次快捷键感知 → 检查发给视觉模型的内容，确认其中包含了主意识最近几轮对话摘要、当前任务背景，且主意识的会话存储未被修改。

**Acceptance Scenarios**:

1. **Given** 主意识刚和人类讨论完某个项目，**When** 人类按快捷键录屏，**Then** 视觉模型收到的输入中包含该讨论的精简背景，其输出能关联到该背景。
2. **Given** 触发了一次感知，**When** 感知处理完成，**Then** 主意识的会话表、会话摘要表、运行日志表的写入数据中没有任何由"视觉上下文构建"产生的痕迹（纯只读）。
3. **Given** 主意识最近一轮思考存在（reasoning），**When** 构建视觉上下文，**Then** 视觉模型能看到最近一轮的思考内容（用于让视觉模型理解主意识的推理脉络）。

---

### Edge Cases

- **快捷键 daemon 未启动 / 崩溃**：主意识不受影响，正常处理飞书消息等其他事件；感知能力暂时不可用，应有可观测的状态（日志）。
- **录制时无音频（麦克风静音/未授权）**：视觉模型仍能基于画面给出理解；音频部分标记为不可用，不阻塞整体流程。
- **录制时屏幕无变化（黑屏/锁屏）**：视觉模型应能识别"画面无有意义内容"并给出低价值判断；仍注入事件但 summary 标注低价值。
- **主意识长时间无活动（无 session）**：视觉上下文构建时取不到 turns/wake meta，应优雅降级为"无背景"，视觉模型仍可处理（仅看画面）。
- **视觉/ASR 模型调用失败（限流、网络、超时）**：不阻塞感知流程；尽量降级（如视觉失败但 ASR 成功则只注入语音转写），并明确标注哪部分失败。
- **录制超过最大时长**：自动结束并按正常流程处理（已在 US1-AC5 覆盖）。
- **daemon 配置的默认实例不存在或已下线**：endpoint 返回明确错误（4xx），不静默丢弃；人类可被引导修正配置。
- **录屏包含敏感信息（密码、私聊）**：本期不做内容审查（列入未来工作），但在文档中明确告知人类此风险，由人类自行决定何时触发。

## Requirements *(mandatory)*

### Functional Requirements

**感知触发与采集**

- **FR-001**: 系统 MUST 提供一个独立于数字生命主进程的感知采集程序，它能在人类登录电脑后常驻，监听全局快捷键，并在持有系统权限的前提下录制屏幕与麦克风音频。
- **FR-002**: 采集程序 MUST 支持"按一次开始、再按一次结束"的开关式录制，并 MUST 设定一个最大录制时长，超时自动结束。
- **FR-003**: 采集程序 MUST 在录制结束后，将原始媒体文件落盘保留（供主意识事后回看）。

**预处理（视觉/音频流水线）**

- **FR-004**: 系统 MUST 对录屏做时间维度（降低采样频率）和空间维度（降低分辨率）的压缩，以受控的体积传给视觉模型。
- **FR-005**: 系统 MUST 将录音转写为文字；对超出单次转写时长的录音，MUST 自动分段处理并在分段间保持上下文连贯。
- **FR-006**: 当视觉模型理解与语音转写中某一项失败时，系统 SHOULD 降级使用可用的那一路结果，并明确标注缺失的部分。

**视觉模型理解（带上下文）**

- **FR-007**: 系统 MUST 在调用视觉模型前，从主意识的会话数据中**只读地**构建一份精简上下文，包含：最近若干轮主对话、当前任务/唤醒背景、（如有）已结束会话的摘要。
- **FR-008**: 系统 MUST 在精简上下文中保留主意识最近一轮的思考（推理内容），让视觉模型能理解主意识的推理脉络，且 MUST 在数据格式上做最小适配以兼容视觉模型的输入协议。
- **FR-009**: 精简上下文的构建过程 MUST NOT 向主意识的任何持久化存储（会话表、会话摘要表、运行日志表等）写入数据。

**事件注入与实例归属**

- **FR-010**: 系统 MUST 提供一个内部接口，将视觉模型的结构化理解结果作为"感知信号"事件注入指定数字生命实例。
- **FR-011**: 感知信号事件 MUST 复用现有的唤醒/注入机制：当目标实例空闲时触发唤醒；当目标实例正在思考时，平滑注入其内存信号池，不打断当前推理。
- **FR-012**: 系统 MUST 支持多实例部署下的实例路由——采集程序默认指向一个配置指定的实例，并允许在触发时显式覆盖目标实例。
- **FR-013**: 感知信号 MUST 作为一种新的事件类型注册，拥有与其他事件类型一致的属性（显示名、优先级、唤醒提示、可用工具集、消费策略）。

**模型主动观察**

- **FR-014**: 系统 MUST 为主意识提供主动观察工具（看屏幕、看摄像头、听麦克风），其内部复用与快捷键相同的视觉/音频流水线。
- **FR-015**: 主动观察工具 MUST 作为普通工具同步执行，结果作为工具返回值进入思考流，而非产生新事件。

**可观测性与健壮性**

- **FR-016**: 感知系统的各环节（采集、预处理、视觉理解、事件注入、实例路由）MUST 产生可检索的日志，便于诊断"为什么没看到/为什么理解错了"。
- **FR-017**: 当任一环节失败时，系统 MUST NOT 导致主意识进程崩溃或卡死；失败被捕获、记录、降级。

### Key Entities *(include if feature involves data)*

- **感知信号（Perception Signal）**: 一种新的事件类型。关键属性：来源（快捷键-视觉 / 快捷键-音频 / 快捷键-两者 / 模型主动-屏幕 / ...）、一句话摘要、结构化详情、原始媒体文件路径。
- **精简视觉上下文（Slim Visual Context）**: 一次性构建、仅供视觉模型本次调用使用的只读数据包。来源是主意识的会话/日志数据，但不被持久化为独立实体（用完即弃）。
- **感知采集会话（Capture Session）**: 一次"按下→再按下"之间的录制过程。关键属性：起止时间、媒体文件路径、触发来源（快捷键/模型主动）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 人类从结束录制（按下第二次快捷键）到主意识开始处理感知信号，端到端延迟在常规场景下不超过 60 秒（含视觉/ASR 模型调用）。
- **SC-002**: 在主意识有明确进行中任务的场景下，视觉模型给出的理解结果中，超过 70% 的内容能被人类判定为"与当前任务相关"（而非泛泛的画面描述）。
- **SC-003**: 触发感知信号时，主意识正在进行的思考/工作不会被打断或损坏（感知信号仅在思考间隙被纳入，0 例因感知注入导致主意识推理中断）。
- **SC-004**: 感知系统任一组件（采集 daemon、视觉模型、ASR、事件注入）失败时，主意识仍能正常处理其他来源的事件（0 例因感知组件故障导致主意识不可用）。
- **SC-005**: 多实例环境下，连续 10 次快捷键触发，感知信号全部被路由到配置指定的实例（0 例误路由）。
- **SC-006**: 触发感知信号后，主意识的会话存储校验和（会话表、摘要表、运行日志表的写入记录）与未触发时一致（0 例未授权写入）。

## Assumptions

- **运行环境**: 部署在 macOS（Apple Silicon / Intel）的登录用户会话中；人类愿意授予采集程序"屏幕录制""麦克风""辅助功能/输入监控"等系统权限。
- **本机部署**: 采集程序与数字生命主进程运行在同一台机器上，通过本机回环地址通信（本期不考虑跨机/远程采集）。
- **模型可用性**: 智谱 GLM 系列视觉模型与语音转写模型可用，且使用与主意识相同的 API 凭证（同一平台、同一密钥体系）。
- **单实例为主**: 多实例部署时，人类通常有一个"主交互实例"，作为采集程序的默认目标；按需可覆盖。
- **不在本期范围**: 视觉系统定时自动观察并主动注入（双模型错位方案）——本期设计预留扩展点但不实现；自动操作鼠标键盘/浏览器；语音（TTS）输出。
- **安全边界**: 本期不对录屏/录音内容做敏感信息审查；人类理解并接受触发感知即上传内容至模型服务，由人类自行判断何时触发。
- **复用现有架构**: 事件注入、实例路由、唤醒/注入仲裁等机制完全复用现有实现，不重复造轮子。
