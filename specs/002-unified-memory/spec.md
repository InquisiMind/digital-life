# Feature Specification: 统一记忆体系（Unified Memory）

**Feature Branch**: `002-unified-memory`
**Created**: 2026-07-16
**Status**: Implemented (P1+P2+P3+P4 全部落地, 2026-07-16)
**Input**: User description: "统一记忆体系：切片原子 + 三类连边网 + 认知演化生命周期。承接主设计第九章，统一记忆子系统的写入归一、检索融合、投递调度与认知演化机制。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 缺口补丁：让现有记忆管线不再丢数据 (Priority: P1)

> **起点阶段**。在不动现有存储结构的前提下，修复当前记忆链路里三个确认存在的破洞，
> 把系统修补到"能正常工作"，为后续重构拿到干净的对照基线。

具体三件事：

1. **segment 叙事摘要不再蒸发**。会话被消化为 segment 叙事摘要后，该摘要今天被写进
   归档表但**从不进入检索池**——模型最该读到的"第一人称经历"，在检索里压根不存在。
   P1 要让 segment 摘要成为可被检索的一份内容。

2. **segment 实体提炼不再静默崩**。`update_entity_index_from_narrative` 调用的
   `entity_index.add_entity` 是**死函数**（不存在）——这意味着 segment 提炼流程每次都抛
   `ImportError`，被 try/except 静默吞掉。P1 要修这个调用，让 segment 提炼的实体产物真正落地。

3. **嵌入服务下拉即退化、不再静默失败**。当前嵌入客户端对 429 / 超时 / 批内部分失败
   三种情况都**全批丢弃并静默 debug 日志**——智谱余额为 0 时整个向量召回路线直接瞎。
   P1 要让它能局部成功、能重试、能在失败时被看见。

**Why this priority**：在一个**残破**基线上做重构，新 bug 和旧 bug 搅在一起无法区分贡献。
P1 是零架构影响、立即可见效的修复，**给 P2/P3 提供对照基线**。

**Independent Test**：可以独立上线、独立验收。完成后召回质量应当小幅回升、
segment 摘要料进库、实体提炼不再报错、嵌入 API 失败时控制台可见。

**Acceptance Scenarios**:

1. **Given** 一段会话被消化生成 segment 叙事摘要，**When** 触发一次相关语义检索，
   **Then** 该摘要内容应当出现在候选结果里（而非凭空消失）。
2. **Given** segment 叙事内部提到若干实体，**When** 消化流程执行完毕，
   **Then** 这些实体应当被正确写进实体索引（不再因死函数调用而静默失败）。
3. **Given** 嵌入服务返回 429（余额不足），**When** 客户端发起一次调用，
   **Then** 失败 MUST 以可见级别日志暴露（而非 `debug` 沉默）、**不做重试**、
   降级到词法兜底路（不再因单个失败全批丢弃，批内已成功项保留）。
4. **Given** 嵌入服务完全不可达，**When** 发起召回检索，**Then** 系统应当降级到词法路径
   完成召回（消费侧不感知），且记录一次失败。
5. **Given** P1 修复上线后，**When** 跑记忆召回评估脚本，**Then** 召回率/命中数应相比修复前
   基线有提升或至少不下降（不引入回归）。

### User Story 2 - 统一检索面：三路融合、单一 facade (Priority: P2)

> **第二阶段**。让分散的三条检索路径（实体触发 / 向量语义 / 工具按需）收敛成**一份
> 融合后的排序结果**，并补一条**不依赖外部 API 的词法兜底路**。

具体能力：

1. **统一检索入口**：常驻 / 被动触发 / 模型按需三种投递时机，**调用同一份检索面**，
   只在调度规则（多少条、什么源、什么预算）上不同。今天三者各自直连
   `query_entities_ranked` / `recall_memory` / `sense_entity`，存在行为漂移。

2. **三路候选融合**：语义相似路（整段向量）+ 词法兜底路（中文分词 + 词频排序）+
   实体 / 注意力提权，三路各自产候选 → 统一打分融合 → 去重排序 → 一份结果。
   替代今天"实体路结果 + 向量路结果**字符串拼接 + 30 字符前缀去重**"的脆弱合并。

3. **网状回忆**：命中一个记忆点时，把它的**时序邻居**（同会话 / 同日前后）和
   **诞生链上游**（认知是怎么来的）一起作为候选拉进来——让一个点唤起一簇。

**Why this priority**：设计文档 §4–§5 的核心产品价值（三路融合 + 网状回忆）落在这一阶段。
P1 已经把现状修好，P2 才有干净的对照去评估融合算法带来的真实增益。

**Independent Test**：可独立于 P3 上线。统一检索面切换完成后，三种投递时机的返回方式
改为调用同一接口（行为向"融合后"统一），召回评估的真实金标应当好于单路。

**Acceptance Scenarios**:

1. **Given** 上下文里出现一个实体名，**When** 触发被动投递，**Then** 返回里应同时
   包含该实体相关碎片（语义路）、含同一实体名的其它切片（词法路）、以及同会话时序上相邻的切片，
   按一份统一排序而非拼接呈现。
2. **Given** 嵌入服务整条线失效（429 持续 / API 不可达），**When** 发起任意一次召回，
   **Then** 词法路独自承担召回、返回非空结果（不再像今天一样**整条回收半瘫**）。
3. **Given** wake 召回 / mid-session 联想 / `sense_entity` 三个调用点，
   **When** 它们各自请求记忆，**Then** 它们必须经过同一个统一检索入口
   （可由代码静态确认：三处 import / 调用均指向同一模块），调度参数差异显式可读。
4. **Given** 一条认知切片（例如某条规则 / 教训 / 概念卡），**When** 它被检索命中，
   **Then** 它的时序诞生上游（formation 来历）可作为候选被一起浮现（按召回配额）。
5. **Given** 一条历史会话的两个相邻片段，**When** 其中之一被命中，**Then** 另一片段
   作为时序邻居有显式权重加分（不再仅靠语义凑巧命中）。

### User Story 3 - 切片层重构：写时异构、读时同构 (Priority: P3)

> **收尾阶段**。把当前共享但形状未统一的存储载体，**结构性地升级为统一切片层**——
> 承载经历 / 认知两种相位、三类连边元数据、以及参数演化引擎的运行时字段。

具体能力：

1. **统一切片原子**：所有可检索内容（经历摘要 / 日记 / 洞察 / 规则 / 教训 / 概念卡 / …）
   都归一成同一种形状——带正文、相位、来源类、权威 / 抗衰参数、实体引用、时序元数据、
   诞生链指针。一份原子形态、一个写入接口、一套读取路径。

2. **三类连边元数据落地**：切片携带 `time_meta`（时序连续）、`derived_from`（诞生链）、
   以及整段 embedding（内容相似）三类连边的元数据，使 P2 的网状回忆建立在结构化字段上
   而非临时计算。共现联想作为第四类弱增强边叠加。

3. **参数演化引擎第一阶段**：把"时衰降权 / 参考计数 / 归档阈值"这些今天散落各处的
   零散规则，收敛成**统一值驱动**的函数族——新增一类记忆只新增一组基线值，不写代码分叉。
   这是认知演化生命周期的"自动驱动器"半边（见 §User Story 4 的另一半）。

**Why this priority**：P1/P2 已让检索与召回正常工作并融合；P3 把原子形态和演化机制做实，
但**依赖 P1 的数据干净 + P2 的检索面就绪**才能切换而不破坏行为。

**Independent Test**：分步切换 + 数据迁移验收。切换后所有写入 / 读取点复用同一个原子形态；
监控页（控制台 chunks 视图）能展示新切片属性；既有召回行为不允许整体退化。

**Acceptance Scenarios**:

1. **Given** 任何一类记忆源（结论 / 经历 / 规则），**When** 它被写入检索池，
   **Then** 都应当以同一原子形态存储（字段齐备），可在监控页查看到统一字段。
2. **Given** 一条原本以旧格式存在的历史切片，**When** P3 上线迁移运行，
   **Then** 它应被无损转换为新的统一原子形态（关键字段不再缺失），且能被检索命中。
3. **Given** 新增一种记忆来源（例如项目档案文档），**When** 接入统一切片层，
   **Then** 只需提供一个"归一器"把它的内容转成切片原子、提供一组基线值——
   检索 / 演化 / 投递逻辑**零修改**就能让新源生效。
4. **Given** 一条认知切片，**When** 它经历多次被检索并显示后被长时间未访问，
   **Then** 它的可见性按统一时衰规则下降（数值可观察），而非散落在多个分支里各算各的。
5. **Given** 三个重叠对话库、11 个 markdown 记忆文件，**When** 评估其合并必要性，
   **Then** 这些层迁移**显式排除在 P3 范围外**（见 §Out of Scope），P3 只做统一原子 + 检索面切到新层。

### User Story 4 - 认知演化生命周期：会成长、不偏执 (Priority: P4)

> **延伸阶段**。设计文档 §6 的重心——认知形成之后的**持续变化**机制。
> 是本设计真正让生命体"越用越聪明"的发动机。

具体能力（与自动驱动器接续）：

1. **认知的状态机**：认知切片的生命周期状态——`nascent → active → reinforced/revising/challenged
   → archived/replaced/higher`——以及跃迁规则。永不硬删，所有"消失"都是降级归档、可溯源。

2. **三条防偏执铁律**：
   - **"想"不强化**：被动命中只动短期活跃度，不动权威/验证度；
   - **强化专属认知类**：经历类只会作为"应晋升候选"微涨，只有已成为认知才接受结构性强化；
   - **强化是晋升的结果不是原因**：晋升因为"经历反复触及"，强化发生在晋升之后。

3. **认知形成**：A 路径——经历反复触及同一节点 → 模型主动提炼成认知切片（晋升）；
   B 路径——对已有认知做语义聚类 → 模型形成更高阶新认知（"从大量教训里抽象出行为哲学"）。
   规则只做时衰 / 计数 / 归档，晋升与诞生一律模型驱动。

4. **反偏置的健康遗忘**：长期无新证据支持且无矛盾触及的高权威认知，
   降它在排序里的**可见性**（不降事实权威）——"长期不被印证的真信念，安静地变成背景"。

**Why this priority**：最高阶的"心智成长"机制，依赖前三阶段搭好的原子、检索网、参数引擎。
是真正的方向但实现复杂、阈值敏感，留作专项细化。

**Independent Test**：可分能力上线。状态机先上、防偏执铁律紧随、聚类诞生新认知最末。

**Acceptance Scenarios**:

1. **Given** 一条认知被频繁被动命中（"想了很多次"），**When** 经历若干轮后查看其参数，
   **Then** 它的权威度 / 验证度**不变**（防回声室）；只有被采纳 / 实践正反馈才计验证度。
2. **Given** 一段经历切片被反复命中同一认知节点，**When** 模型在整理周期检查到此信号，
   **Then** 模型产出一个晋升动作：经验提炼为认知切片、经历被吸收裁剪、诞生链保留可溯源。
3. **Given** 一条认知被新证据反驳，**When** 反证计数升高，
   **Then** 该认知进入 challenged 态、权威下降；未及时修订则滑入 archived（**不删，按需可见**）。
4. **Given** 一条新的更准确认知出现并取代旧认知，**When** supersede 发生，
   **Then** 旧认知标记 `supersede_by → 新`、新认知 `derived_from += [旧]`，链路完整、可回看成长轨迹。
5. **Given** 多条关于同一主题的成熟认知，**When** 它们语义相近被聚类，
   **Then** 提交给模型后可形成一条更高阶的新认知（泛化 / 抽象），新认知反向链接参与聚类的认知。
6. **Given** 一条高权威认知长期（远超阈值）不被新证据支持或反证触及，**When** 排序其候选项，
   **Then** 它在排序中的可见性下降（但事实权威不变），让位给有近期证据的认知。

### Edge Cases

- 嵌入服务持续不可用（余额耗尽持续数日）：词法路必须独立维持可用，且需要用户可见的健康指标。
- **检索超时（单次任意子路径耗时超过硬上限）**：MUST 返回当前已累积的部分结果向消费侧投递，
  **不得阻塞正常工作流**；消费侧不感知失败（符合 FR-104 / FR-001）。
- 同一会话产生大量 segment 摘要导致索引膨胀：需要批量归一与去重边界，§Risk。
- 历史数据中存在格式残破或字段缺失的旧切片：迁移必须做无损 / 兜底，而非直接丢弃。
- 晋升 / 取代 / 聚类等模型驱动操作失败或产生低质量结论：退化策略须明确（保留原状 + 标记待复审）。
- 多实例并发触发同一记忆写入：须避免重复切片 / 重复归一。
- 用户不同的 raw 实例（交易 / 陪伴）语言与领域差异显著：分词 / 语义阈值不应硬编码,
  须经真实实例的可调配置或自适应。

## Requirements *(mandatory)*

### Functional Requirements

**通用要求（贯穿 P1–P4）**：

- **FR-001**: 记忆系统 MUST 保证**检索永远不是关键路径阻断点**——任一检索子路径失败，
  须自动退到下一路；全部子路径弱化时，依靠常驻 / 工作层兜底；消费侧不感知失败。
- **FR-002**: 所有切片的**合并 / 覆盖 / 晋升 / 衰减 / 归档 MUST 共用同一套管线**；
  不同来源类别的差异**只能体现在切片携带的数值参数上**，不允许在管线代码里按来源分叉。
- **FR-003**: 系统 MUST 持久化所有**记忆演化的可溯源性**——任何取代 / 修订 / 归档 MUST
  保留历史版本及 `derived_from` / `supersede_by` 链，永不硬删。

**P1 缺口补丁**：

- **FR-101**: 任何一段被消化生成的内容（segment 叙事摘要）MUST 被归一为可被检索的切片，
  不得在 archive 后直接"蒸发"。
- **FR-102**: segment 提炼流程产出的实体 MUST 被正确写入实体索引；调用不存在的函数
  造成静默失败 MUST 被根除。
- **FR-103**: 嵌入客户端 MUST 区分三类失败（429 限流 / 网络超时 / 批内部分 null）
  并采取各自策略：**429 / 超时 / 不可达 不做重试，直接透传失败**
  （见 Clarifications Session 2026-07-16），部分失败保留批内成功项；
  任何失败 MUST 以可见级别日志暴露。
- **FR-104**: 整体检索 MUST 设一硬时间上限（默认 5 秒，可配置），
  超时即返回当前已累积的部分结果向消费侧投递，**不允许阻塞正常工作流**。
  （与 FR-001"检索永远非阻断点"互为具体落地。）
- **FR-105**: P1 在为 segment 切片补齐检索入口的同时，MUST 顺便预埋 P3 的相位字段
  （`phase=experience`），P1 消费侧不读这些字段但 schema 已就位——避免 P3 二改表结构。

**P2 统一检索面**：

- **FR-201**: 系统 MUST 提供单一检索入口（facade），常驻 / 被动 / 按需三种投递 MUST 通过它；
  调度差异须显式参数化，不允许三路径各自直连底层。
- **FR-202**: 检索 MUST 至少包含两条独立路：**整段语义** + **离线词法兜底**；二者各自的失败
  MUST 相互独立，不形成相互阻塞。
- **FR-203**: 多路结果 MUST 经一个统一融合算法产出**一份排序**，NOT 字符串拼接；
  去重 MUST 基于切片身份而非文本前缀。
- **FR-204**: 检索 MUST 产出**时序邻居候选**与**诞生链回溯候选**，与语义 / 词法候选一起进入融合。

**P3 切片层重构**：

- **FR-301**: 所有可检索单元 MUST 归一为统一切片原子形态，携带相位（经历 / 认知）、
  来源类、权威 / 抗衰 / 验证 / 时间 / 诞生链等字段。
- **FR-302**: 系统 MUST 提供切片**迁移路径**：旧格式切片无损转换为原子形态，可被检索命中。
- **FR-303**: 新增一类记忆来源 MUST 只需：一个归一器（转成切片原子）+ 一组基线值；
  无需改动检索 / 演化 / 投递代码。
- **FR-304**: 时衰 / 参考计数 / 归档 MUST 由**单一值驱动的函数族**计算，不允许散落在多处。

**P4 认知演化**：

- **FR-401**: 被动命中（"想"）MUST 仅影响切片短期活跃度，**不得**改变其权威度或验证度
  （防回声室铁律一）。
- **FR-402**: 结构性强化（正反馈 / 反证）MUST 仅作用于**已成认知**的切片；经历类 MUST 仅作为
  晋升候选信号被微涨（铁律二）。
- **FR-403**: 晋升 MUST 由模型驱动并留 `derived_from` 链；经历切片被吸收 MUST 保留可溯源性。
- **FR-404**: 认知切片 MUST 支持 `supersede` 跃迁——新认知出现时旧认知标 `supersede_by`、
  新认知纳入 `derived_from`，链路完整可回看。
- **FR-405**: 系统 MUST 提供**健康遗忘**：长期无新证据 / 无反证触及的高权威认知，
  其**排序可见性**下降（**不**降其事实权威度）。
- **FR-406**: 高阶认知形成（聚类 → 模型抽象）MUST 以可关闭、可降级的方式提供——
  产出质量不达标时退化为保留原状 + 标记待复审。

### Key Entities *(include if feature involves data)*

- **Slice（切片）**：检索 / 演化 / 投递的唯一原子。带正文、相位（experience/cognition）、
  来源类、参数（权威/抗衰/验证/活跃/证据/反证）、实体引用、时序元数据、诞生链。
- **Cognition Node（认知节点）**：导航骨架，表示"某实体 / 概念 / 人 / 项目"；
  切片通过 `entity_links` / `attention_tokens` 挂靠其上。检索期点亮节点 → 拉挂靠切片候选。
- **Phase（相位）**：experience（经历）/ cognition（认知）—— 决定参数基线与晋升逻辑。
- **Forces（信号）**：驱动参数演化的输入——时间流逝 / 被召回 / 被采纳 / 正反馈 / 反证 / 冲突。
- **Cognition State（认知状态）**：nascent / active / reinforced / revising / challenged /
  archived / replaced / higher。
- **Edge（连边）**：三类生成法则——时序连续 / 诞生链 / 内容相似；共现联想作第四类弱增强。

## Success Criteria *(mandatory)*

### Measurable Outcomes

**韧性（贯穿全部阶段）**：

- **SC-001**: 当嵌入服务整条线不可用时，召回 MUST 仍能返回非空结果（词法路兜底）——
  这是"数字生命不该因某家 API 挂掉就失忆"的产品承诺。
- **SC-002**: P1 上线后，segment 叙事摘要 MUST 进入检索池可见；记忆召回评估的命中数、
  召回率相比修复前基线不下降（不引入回归）。
- **SC-003**: 嵌入服务 429 场景下，客户端的失败 MUST 在控制台以可见级别日志暴露
  （而非 `debug` 沉默）；**不做重试**（见 Clarifications），直接降级到词法兜底路
  （符合 FR-001 / FR-103 / FR-104）。

**召回质量（P2 重心）**：

- **SC-004**: 在独立金标评估集（非自派生）上，统一融合检索的召回率 MUST 不低于
  各单路的并集；用以对照的现有 eval baseline 须保留供对比。
- **SC-005**: 召回结果里**重复或近似冗余的切片**占比 MUST 低于当前字符串拼接方案
  （30 字符前缀去重）的水平。

**可扩展性（P3 重心）**：

- **SC-006**: 新增一类记忆来源所需改动量 MUST 显著小于改造前——以"归一器 + 一组基线值"
  为目标，存量检索 / 演化 / 投递代码零修改。
- **SC-007**: 全部切片的衰减 / 归档 / 计数逻辑 MUST 集中在单一函数族；
  以静态扫描确认代码中不再存在散落在多模块的并行衰减算法。

**心智成长（P4 重心）**：

- **SC-008**: 一条被频繁被动命中的认知，N 轮后其权威度与命中前**相等**（防回声室铁律一可测）。
- **SC-009**: 晋升 / 取代 / 聚类任一跃迁发生时，系统 MUST 留下完整可溯源链
  （`derived_from` / `supersede_by` / version）；旧版本永不丢失。
- **SC-010**: 新认知取代旧认知、新认知随后被反证，旧链路 MUST 仍可回溯到最初认知,
  即"我曾这么想过"完整保留。

## Clarifications

### Session 2026-07-16

- **Q: P1 修复 segment 索引时,切片仅追加进检索池,还是顺便预埋 P3 的 phase/权威/时效等字段?**
  → **A: 进索引 + 预埋相位。** P1 阶段在补 segment 切片进检索池的同时,就直接打上
  相位字段（`phase=experience`），P1 消费侧不读这些字段，但字段存在。这样 P3 统一迁移时
  无需回头改表 schema，避免双改。理由：贴合设计文档"拍平"精神。
- **Q: P2 召回的每轮 token 预算是精确计数还是字符近似?**
  → **A: 不卡预算（P2 阶段）。** P2 聚焦在召回质量与融合效果，不引入 tokenizer 模块。
  token 预算约束推迟到 P3 验收期，依据实际占用实测后再定档。
- **Q: P1 嵌入重试该多重?**
  → **A: 不重试,但设置检索时间上限。** 429 / 超时 / 不可达 → 直接透传失败并降级到词法兜底路,
  **不在召回路径做重试**（避免 429 风暴 / 避免召回阻塞）。整体检索设一硬上限（默认 5 秒，
  可配置），超时即返回当前已有结果，**确保不阻塞正常工作流**。这条与 FR-001"检索永远非阻断点"
  是同一个铁律的精确落地。



- 用户的多实例（交易 / 陪伴 / 学习）继续各自隔离，本 feature 不引入跨实例实体共享
  （第九章 9.7 已列为已知边界，本 feature 显式不破）。
- 智谱 Embedding-3（2048 维）继续作为语义嵌入服务；用户充值后 Route B 路自然恢复，
  P1 的客户端韧性是为其失灵兜底，不替换服务方。
- 参数阈值、边权重、扩散深度等机制常数，按设计文档 §0 之意，**不在初版定死**——
  机制建立后跑真实数据来调，本 feature 不交付最终阈值表。
- memory_hygiene / dream（第九章 9.4 描述的"模型消化碎片"周期）继续作为认知驱动的
  执行器存在，本 feature 复用它作为 model_* 信号的产出来源，而非新建一套。
- **存储层合并显式排除**：三个重叠对话库（messages.db / state.db.messages / conversation_log）
  的合并、11 个 markdown 记忆文件入库，**不在本 feature 范围**——
  主设计已指明这是更大的层迁移，风险大于本 feature 价值。
  统一检索面建好后，未来迁存储只替换"源→消化"段，检索段原样复用。
- 评估基线：scripts/eval_memory_recall.py 当前从 entity_index.json 自派生 100 例、
  结构性偏向实体路；本 feature 在 P2 必须补一份**独立金标集**和**精度 / token 成本**指标，
  避免用偏向数据评估偏向。
- 本 feature **不接入**冷启动旧记忆的 retroactive 重新归一（第九章 9.7 已列为已知边界）；
  P3 迁移只对存档中已存在的切片做无损转换，不主动补挂实体标签到从未标注过的旧数据上。
