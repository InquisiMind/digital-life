# ADR-0002：token_budget_monitor v2（含目录卫生巡检）
- 状态：proposed ｜ 日期：2026-08-31 ｜ 提案人：Alpha（设计稿）/ Zero（review）｜ 决策人：zhp（待）

## 背景与动机
monitor v1 无法感知企业版席位体系（月周期+超量模式、报错语义归零——余额报错一律显示
"无余额"，判别力为 0，唯一判别词=页面产品名）。同时 8/26-27 暴露实例上下文串扰三症
（拼接目录 / instance_channel 交叉 / budget_log 跨库记账），需要探测网。

## 决策（决策级要点，详见设计稿）
1. 双池框架：个人池（按实例）+ 企业池（席位制，月周期+超量）分列。
2. 目录卫生巡检：`apps/` 白名单=三个正版全长 UUID **精确等值集合**（正则层无效——拼接体是
   合法 UUID；前缀匹配无效——_trash 拼接体与正版共享前 18 位）。再生即告警，作为实例上下文
   串扰根因的探测网；根因修复单独立项（master 层，zhp 拍板）。
3. 记账口径：分子=三库各自全量之和，**禁止按 instance_id 过滤**（群 session 跨库记录的
   instance_id 记的是发送者不是消耗者，标签串位但总和守恒；同 session±5s 对侧库 0 命中，
   无双计）。分子标注"zhp-key 覆盖，τ 除外（key 待确认）"。
4. 部署：定稿后设计稿归档至 docs/architecture/，脚本归 scripts/。

## 备选方案
- 沿用 v1+人工对账：企业池完全盲区，弃。
- τ 侧迁移 monitor：跨库读取未打通前分子缺位，先双库+标注，迁移进 backlog。

## 影响面
新增 scripts/ 监控脚本（定时 launchd）；无侵入读取三库 budget_log。

## 验证方式
席位报错注入测试（页面产品名判别）；拼接目录样本回放（白名单拦截率 100%）；
月周期翻转日对账。

## 回退方式
launchctl unload monitor plist；git revert。
